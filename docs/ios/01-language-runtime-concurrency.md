# iOS 01｜Swift 语言特性、运行时与并发

Swift 的特点体现在几组相互关联的选择中：用 Optional 和关联值枚举表达数据状态，用结构体与标准集合提供值语义，用协议和泛型保留类型之间的关系，用 ARC 管理共享对象的寿命，再用任务和 actor 组织异步执行。读懂 Swift 代码，需要把声明、数据关系与运行行为连接起来。

已有 JavaScript、Dart 和 Flutter 经验，可以直接从这些具体规则进入。尤其需要注意，Dart 中习惯通过对象身份理解的数据，在 Swift 中可能是独立的值；熟悉的闭包和异步写法，也会受到捕获、ARC 与隔离规则的共同影响。本篇按这些关系保留机制解释，具体写法与运行关系后续结合真实应用阅读。

## 类型与数据表达

### 类型推断、绑定与转换

Swift 支持类型推断，但数字字面量的类型会受到上下文影响：没有额外约束的整数字面量通常推断为 Int，浮点字面量通常推断为 Double；放入参数、属性或集合后，则要满足相应声明的类型。编译器能补出类型，并不表示数值类型之间都能隐式转换。读取平台 API 时，经常需要在 Int、固定宽度整数、浮点数和框架数值类型之间明确转换。

转换还包含数据能否保留的问题。整数类型有范围，浮点表示有精度限制；截断、舍入、溢出与转换失败分别有不同 API。普通整数运算溢出会触发陷阱，显式的溢出运算则采用另外的语义。对于外部输入，能够返回 Optional 的精确转换可以把超范围情况留给调用者处理。

let 与 var 控制绑定的可变性。结构体的 let 绑定不能修改自身存储属性，也不能调用修改自身的 mutating 方法；类的 let 绑定固定的是对象引用，仍可修改该对象允许变化的属性。因而，“这份变量不可重新赋值”与“整个对象图不可变化”在 Swift 中要分别判断。

元组可以临时组合不同类型的数据，标签帮助说明各项含义；当这组数据需要稳定的身份、校验规则、方法或协议遵循时，命名类型通常更合适。Any 能保存不同类型的值，AnyObject 限定类实例，但经这类接口读取数据时，具体能力要靠转换或其他约束重新获得。

### Optional：让缺失成为类型的一部分

Optional 是标准库枚举，包含有值和缺失两种情况，有值时还携带原类型的数据。它可以包装整数、结构体、类实例乃至另一个 Optional。nil 表达的是缺失，数值零、空字符串、空数组都可以是正常的有值状态。Optional 本身不解释缺失原因；“查无结果”和“输入格式错误”是否需要区分，由接口契约决定。

解包既取得内部值，也选择缺失时的控制路径。if let 适合只在当前成功分支使用数据；guard let 将不满足前提的路径提前退出，使后面的语句建立在已取得值的条件上。可选绑定得到的是新的局部绑定：重新给这个局部值赋值，不会自动写回原 Optional；若内部是类引用，它们仍可能观察同一对象。

可选链在中间值缺失时跳过后续访问，最终结果继续表达“这次访问可能没有值”。空值合并则在缺失时才求取默认表达式。默认值会将多种输入折叠成同一个结果，例如把缺失昵称与真实填写的“匿名”显示成一样；展示层可以需要这种处理，领域数据却未必适合过早合并。

Optional 的 map 适合转换已有内容，缺失时不调用转换；当转换自身也返回 Optional，map 会保留两层状态，flatMap 则将这次转换产生的层级展平。字典查询也会增加一层 Optional：保存的值本来就可缺失时，需要区分“没有这个键”和“有键但保存了缺失值”。理解每一层由谁引入，才能判断解包或展平是否丢掉了有用信息。

强制解包依赖调用者保证此时有值，违约会触发陷阱。隐式解包 Optional 同样仍然可能缺失，只是在某些需要内部类型的上下文中自动解包；它常见于初始化顺序受到外部框架控制的接口。它们没有消除缺失路径，只是把处理责任从分支转成了运行时约定。

### 枚举、状态与模式匹配

Swift 枚举的各个 case 可以携带不同类型、不同数量的关联值。加载状态因此可以把成功时的数据、失败时的错误分别放进对应情况，而不必维护多个可能互相矛盾的布尔值和可选属性。状态变化时替换整个枚举值，也就同时替换了属于旧状态的数据。

原始值与关联值承担不同职责。原始值为 case 建立稳定的基础类型表示，常用于与存储或外部协议映射；关联值属于每一次构造出来的枚举值，可以随实例不同。由原始值恢复枚举可能失败，因为外部输入不一定对应已声明的 case。

switch 对已知枚举情况进行穷尽检查。显式处理各个状态，可以让类型新增情况时暴露遗漏；default 便于统一处理其余情况，也可能掩盖本应重新审视的分支。对于启用库演进的外部非冻结枚举，调用方还要面对未来 case，@unknown default 用来处理未知情况，同时帮助诊断当前已知情况的遗漏。

模式匹配将条件判断与数据提取放在一起：可以解构元组、读取关联值、匹配 Optional，再附加 where 条件。只关注一种状态时，可使用 if case、guard case 或 for case，而不必先判断再做第二次取值。is 检查类型关系，as? 在转换失败时返回缺失，as! 则依赖转换必定成功的约定。

### String、索引与集合

String 以 Unicode 文本语义组织字符。一个 Character 可以由多个 Unicode 标量组成，同一个可见字符也可能有不同的编码序列；Swift 的字符串相等比较考虑规范等价，因此字符相等并不要求 UTF-8 字节逐项相同。字符数、标量数、字节数分别回答不同问题，表单字数限制和网络字节限制不能共用一个计数规则。

String.Index 表达文本中的有效位置。获取第几个 Character 需要按字符串的索引规则前进，不能把任意字节偏移直接作为字符位置；修改字符串后，旧索引也可能不再有效。与 C、Objective-C 或以 UTF-16 为单位的 API 交互时，应明确范围来自哪个视图，再完成相应转换。

Array 按位置保存元素，直接下标要求索引有效；Dictionary 按键查询，缺少键是正常结果；Set 表达不重复元素。Dictionary 的键和 Set 的元素需要 Hashable：相等的值必须产生相容的哈希结果，哈希碰撞则仍靠相等比较区分。若类实例作为键或集合成员，其参与相等与哈希的状态在保存期间发生变化，会破坏查找所依赖的条件。

Sequence 提供逐项迭代能力，一次遍历可能消耗其来源；Collection 进一步提供索引、多次遍历等保证。map、filter、compactMap 和 reduce 分别表达转换、筛选、丢弃缺失转换结果与汇总。compactMap 很方便，但解析失败项被丢弃后，调用方也就失去了逐项展示失败的依据。lazy 推迟转换到实际消费时，重复消费还可能重新计算；它不引入异步调度或缓存保证。

标准集合提供值语义。复制一个整数数组后，修改副本的元素不会改变原数组；Array 等使用写时复制，在符合条件时先共享存储，写入需要分离时再复制。外部可以依赖独立值的行为，底层何时分配或复制则由具体实现与优化决定。数组里存着类引用时，两个数组仍可能指向同一批对象，这与数组自身的值语义并不矛盾。

ArraySlice 是原集合的一段视图，保留原来的索引范围，还可能持有远大于切片本身的底层存储。需要长期保留小段内容或使用从零开始的数组索引时，可以转为 Array。Dictionary 和 Set 的遍历顺序不应作为展示或持久化协议，需要稳定顺序时应显式排序。

### 缺失、失败与清理

Optional 适合只需要知道有没有结果的接口；throws 将失败及其原因沿调用关系交给调用者；Result 把成功或失败保存成值，适合缓存、传递或稍后统一消费。三种表达都可能用于一次解析，区别在于调用方需要保留什么信息，以及何时处理结果。

Swift 的 Error 是可以遵循的协议，错误常用关联值枚举表达，以便把失败类别与必要上下文放在一起。普通 throws 允许传播任意 Error；typed throws 将失败类型限制在声明的范围中。同步函数抛错会沿当前调用退出，异步函数的错误则在等待结果时传播，抛错本身不会另建线程或调度任务。

try 标记调用可能传播错误，具体处理由外围 do-catch 或调用者承担。try? 将错误原因折叠为缺失，try! 则要求调用必定成功。rethrows 用于接收可能抛错行为的函数，将其调用是否需要处理错误与传入行为联系起来，集合转换是常见用途。

defer 将清理放在资源取得附近，在离开当前作用域时执行，多个 defer 按注册逆序执行。它只在控制流实际到达该声明后生效，也只覆盖相应作用域退出；给任务设置取消标记但任务还没退出时，清理不会因此立即发生。强制解包、数组越界和前置条件失败属于陷阱，不能通过普通 do-catch 恢复，进程终止也不保证执行作用域清理。

## 函数与类型组织

### 调用表达与函数值

Swift 将外部参数标签作为 API 表达的一部分，内部参数名则服务于实现。合理的标签能说明参数之间的关系，并参与重载解析。默认参数为直接调用提供省略方式；函数转为函数值后，函数类型描述参数类型与返回类型，调用时不会继续保留原声明的标签和默认参数规则。

闭包的尾随写法、参数缩写与返回值推断，可以让接收行为的 API 更紧凑。阅读这样的调用时，需要先看接收方的契约：闭包何时调用、调用几次、是否保存、是否需要隔离，比表面的括号位置更能决定行为。一个尾随闭包既可能同步转换数组，也可能注册未来回调。

非逃逸闭包限定在接收函数返回前使用；escaping 允许接收方保存闭包，使其在返回后仍可调用。autoclosure 将一个表达式包装成无参闭包，供接收方决定是否求值，空值合并的延迟默认值就利用了这类能力。逃逸、延迟与异步分别描述不同事情，只有接收方明确建立任务或调度回调时才产生相应执行过程。

### 捕获、局部状态与 inout

闭包可以捕获创建位置的局部变量，并让这份存储在外部函数返回后继续存在。多个闭包捕获同一个可变变量时，可以共同观察后来的赋值；分别调用一次工厂函数，则可以生成各自独立的捕获状态。闭包由此能表达计数器、回调上下文和可配置行为，无需都做成显式类。

捕获列表在闭包创建时取得相应值。对 Int 等值类型，它可以固定当时的快照；对类引用，它保存的仍是对象引用，不能冻结对象内部数据。普通捕获与捕获列表的差别，需要结合被捕获的是“可变绑定”“值”还是“共享对象”理解。对象是否被继续持有，则还要看捕获的强弱关系。

inout 为调用期间提供可写访问。语言要求调用效果符合传入、修改、写回的模型，编译器可以在满足语义的条件下优化，因而它不等于可任意保存的 C 指针。对同一存储的重叠读写受到独占访问检查限制；属性、下标也可以作为传入位置，因为访问可以通过 getter 与 setter 完成。

独占访问保证和并发同步保证分别解决不同问题。一个调用内部满足了 inout 的独占要求，不代表这个变量可以被其他任务无保护地修改。逃逸闭包也不能把当前调用的 inout 访问长期保存下来，因为调用结束后这项访问承诺已经结束。

### struct、class 与成员行为

struct 表达独立的值，class 表达可共享的对象身份，enum 表达互斥情况。它们都能定义属性、方法与初始化器；class 进一步支持继承和反初始化。Swift 代码中模型和配置经常使用结构体，因为一次赋值或传参可以按值的关系理解；需要多个使用者共同观察同一份状态时，则可以选择共享对象或隔离对象。

结构体与枚举修改自身需要 mutating 方法，这种方法只能用于允许修改的绑定。类方法修改对象属性时不需要相同标记，因为调用方持有的是对象引用。相等关系由 Equatable 等定义，两个内容相等的值不必是同一实例；类身份比较则专门回答是否指向同一个对象。

存储属性直接保存状态，计算属性在访问时执行逻辑，不会因使用属性语法就自动缓存。willSet 与 didSet 响应赋值，也可能在新值等于旧值时触发；初始化器直接建立自身初始属性值，不会照常触发这些观察器。若属性赋值可以导致额外副作用，调用方需要知道这是赋值协议的一部分。

lazy 将存储属性的初始化推迟到第一次访问，之后保留结果。对结构体而言，第一次访问还会写入自身存储，因此不能随意通过 let 绑定触发；它也不自动保证多线程首次访问只初始化一次。下标为类型提供索引式接口，其越界、缺失和修改语义由类型自己定义，不必与 Array 完全相同。

### 初始化、继承与访问边界

初始化器负责让实例进入完整可用状态。结构体在满足条件时可以获得成员初始化器，定义自有初始化后要留意对自动生成入口的影响。可失败初始化通过 Optional 表达无法建立实例；如果调用者还要知道规则为何不满足，可以使用可抛错初始化。

类的两阶段初始化先完成当前类和继承链的存储，再允许进一步定制。子类的指定初始化器要先为自己引入的存储属性提供值，再向父类委托；在第一阶段完成前，不能任意调用实例方法或把尚未完整建立的 self 暴露出去。这使父子类都能依赖自己的存储已经有效，而不必应对半初始化对象。

指定初始化器沿继承链完成构造，便利初始化器提供同类中的替代入口，并最终委托到指定初始化路径。初始化器不会像普通方法那样全部无条件继承，是否继承与子类的存储和自定义初始化有关。override 表示重写父类声明，final 则禁止进一步继承或重写；需要子类都提供的构造入口可以由 required 约束。

扩展适合给已有类型增加计算属性、方法、下标和协议遵循，也可以按条件提供能力。它不能为已有实例直接增加存储属性，也不能替代继承关系随意重写已有方法。按功能拆文件的扩展仍属于同一类型，磁盘目录不会自动形成访问边界。

访问控制与模块一起工作。private 限定在声明及其允许的同文件扩展等范围，fileprivate 限定源文件，internal 是模块默认范围，package 面向同一包内模块，public 公开模块外使用，open 还允许模块外继承或重写。公开接口所暴露的参数、结果和相关类型也必须具有足够可见性，因此“把一个方法标成 public”并不总能单独形成可用的外部 API。

### 包装器、构建器与宏怎样参与表达

属性包装器将可重复的存储和访问策略交给一个包装类型。编译器为被包装属性建立相应存储，普通属性访问经 wrappedValue，额外的 projectedValue 则可以暴露状态或控制接口。它可以实现数值约束、持久化适配等行为，但框架中的状态更新效果还取决于包装类型及框架的具体契约。

结果构建器把一段代码块中的表达式和控制结构转换为构建方法调用，再组合成普通结果。支持哪些分支、循环或可选部分，取决于构建器提供了哪些方法。SwiftUI 的视图声明依赖这类转换，因此表面上排列的多个表达式能够形成一个确定类型的整体，而不是任意异构列表。

宏在编译期生成或补充代码，可以生成成员、遵循或其他声明；编译器仍会检查展开后的结果。它与属性访问时运行的包装器逻辑、对代码块进行组合转换的构建器各有作用。遇到框架提供的属性或宏，需要看清楚哪些能力由语言提供，哪些来自框架生成的实现和运行时协作。

## 协议、泛型与抽象

### 协议要求与扩展派发

协议描述遵循者必须提供的能力，可以要求属性、方法、初始化器，以及关联类型之间的关系。属性要求可以只读或可写，具体实现既可以是存储属性，也可以是满足要求的计算属性。结构体和枚举也能遵循协议，因此复用能力并不依赖共同父类。

协议扩展可以为要求提供默认实现，也可以新增便利方法，两者在调用时有关键差别。协议要求属于遵循关系的一部分，编译器记录类型如何满足它；经泛型约束或协议类型调用时，可以沿这份关系找到具体实现。扩展中额外增加、却没有列为协议要求的方法，则不会自动成为这种可替换入口。

因此，同一对象经具体类型调用一个同名方法，可能使用该类型自己的版本；经协议视角调用时，却选择协议扩展的版本。问题并非对象变了，而是接口承诺中是否包含这项要求。类继承还会增加一层：如果父类借助协议默认实现建立遵循，子类再声明同名方法，不一定能替换既有遵循使用的入口；需要动态重写时，应检查父类是否真正提供了相应类方法。

协议派发、类方法重写和优化后的静态调用不能只凭表面方法名判断。先看调用处知道什么类型、方法是否属于协议要求、遵循在哪里建立，再分析编译器和运行时通过哪条关系选择实现，通常更容易解释实际结果。

### 泛型保留哪些关系

泛型将某些类型选择交给调用方，同时通过约束保留它们之间的关系。一个比较函数若让两个参数共享同一个 Equatable 类型参数，就既要求它们能比较，也要求它们属于同一具体类型；这比“两个值都放进 Any”保留了更多可用于验证操作的信息。

关联类型表达遵循者参与某项能力时使用的数据类型。例如一个数据来源可以关联它输出的元素类型，泛型函数据此保证两次读取得到相同元素类型，而不必事先知道元素究竟是什么。where 约束还能把不同参数的关联类型连接起来，或要求嵌套类型具备额外能力。

条件遵循让泛型容器在内部类型满足条件时才提供某项协议能力。一个包装值只有在内部值可相等比较时，才需要支持整体比较；调用方因此获得准确的可用条件。协议、泛型与扩展的组合可以表达这些约束，避免容器无条件暴露无法兑现的能力。

### some 与 any：隐藏名称和隐藏关系

some 返回类型由实现方决定具体类型，调用方只通过声明的约束使用它，但编译器仍保留这份隐藏类型的身份。同一声明的各条返回路径必须遵守同一个底层类型构造；如果声明本身是泛型，这个类型构造可以依赖其泛型参数。调用时隐藏名称，并不意味着每次都能随意换成无关类型。

any 协议类型则是存在类型容器，可以在运行时容纳不同遵循类型的值。一个列表因此可以保存多种实现，再统一调用协议提供的能力。代价是具体类型以及部分关联关系被隐藏了：两个容器都能读取元素，不代表它们的元素就一定能互相交换；两个值都遵循 Equatable，也不足以证明可直接进行同类型比较。

| 表达方式 | 类型选择 | 接口保留的重点 |
| --- | --- | --- |
| 泛型参数 | 调用方为本次使用确定类型 | 参数、返回值与关联类型之间的约束 |
| some 返回类型 | 实现方确定隐藏的类型构造 | 隐藏具体名称，同时保留类型身份 |
| any 协议类型 | 容器中的值可以来自不同遵循类型 | 统一使用协议能力，支持异构保存与替换 |

some 也可用于参数位置，作为泛型参数的简洁表达，其类型选择方向与返回位置不同。存在类型的能力随着语言版本发展，并非凡是关联类型都不能通过 any 使用；判断依据应是当前操作是否需要被隐藏的类型关系。

### 类型擦除与接口选择

类型擦除通过额外包装，把不同具体实现变成一个稳定的外部类型。包装器可以转发到内部对象，也可以保存执行操作的闭包；关联元素类型等需要保留的信息仍可固定在外部接口中。标准库和框架中的一些 Any 前缀类型使用这种方式，但不能把所有名称含 Any 的声明都视为相同实现。

设计接口时，可以先判断调用方是否需要建立类型之间的关系。需要同类型约束时保留泛型；实现复杂但结果类型稳定时考虑 some；确实要保存异构实现或运行时替换时再选择 any 或专门的擦除包装。不同方式带来的间接访问、存储和优化机会依实现而异，不能仅按语法推断性能高低。

## 内存、捕获与所有权

### 值复制与对象共享

Swift 的值语义保证的是独立值的可观察行为，不等于每次赋值都立即逐字节复制，也不等于结构体一定在栈上、类实例一定对应一次可见的堆分配。编译器可以消除分配、共享集合存储或改变表示，只要保持语言承诺的行为。

结构体里可以包含类引用，数组也可以保存对象。复制外层结构体或数组，只会按各成员本来的语义复制：内部引用仍可能指向同一对象。修改副本自身的属性，与经副本修改共享对象，是两条不同的操作路径。判断是否需要深拷贝时，应先画清对象关系，而不是只检查最外层用了 struct 还是 class。

这对已有 Dart 经验尤其重要。Dart 中常见的模型对象通常通过共享身份来理解；Swift 中大量模型、字符串和集合则按值使用。把值当共享对象可能导致修改没有传回原位置，把含引用的值当完整快照又可能意外共享内部状态。

### ARC 如何决定对象寿命

ARC 通过强引用管理类实例寿命。属性、集合元素、局部持有和闭包捕获都可能维持强引用；当对象不再被强持有时，可以销毁实例并执行 deinit。与追踪式 GC 的理解方式相比，Swift 需要更直接地关注持有关系，尤其是对象之间形成的环。

对象 A 持有 B、B 又持有 A，或者对象保存一个强捕获自身的闭包，都可能使外部使用者退出后仍无法释放。环不要求只有两个节点，订阅对象、回调容器和任务捕获都可能参与。排查时需要找出持续存在的强引用路径，以及谁负责在何时移除其中一条边。

局部变量的文本作用域也不应被当成每一项资源的精确释放时刻。优化可以影响最后一次使用后的寿命，withExtendedLifetime 则可在需要时明确保持对象存活。语言实验可以观察特定持有关系的结果，但完整应用中的寿命还受框架缓存、运行时和其他持有者影响。

### weak、unowned 与闭包捕获

weak 不维持对象存活，目标释放后自动变为 nil，因此通常通过 Optional 访问。它适合“使用者可以比目标活得更久”的关系，例如一个可能在页面结束后才被调用的回调。闭包若发现目标已不存在，可以按契约放弃更新或返回备用结果。

unowned 同样不强持有目标，但访问时依赖目标仍有效的寿命约定，违约会触发运行失败。它适合能够证明目标覆盖使用者访问期间的关系；选择它的依据是所有权结构，而不是不想写解包。Optional 形式的 unowned 可以表达空引用，但仍不会像 weak 一样在目标释放时自动清空。

捕获列表让闭包明确选择持有什么。强捕获可以合理地保证一项操作完成前对象仍在，弱捕获则允许对象先结束。只有当强引用关系确实形成了不应持续的环，或操作不应该延长对象寿命时，才需要相应调整；将所有回调统一改为弱捕获也可能让必要工作悄悄失去执行对象。

弱引用在读取后可以被提升为局部强引用。如果这份强引用在挂起点之后仍要使用，它就可能继续保持对象存活。因此，“闭包开始用了 weak”并不等于“整个异步过程都不持有对象”。对于长期任务，需要同时审视任务句柄由谁保存、闭包捕获什么、何时取消，以及任务何时真正退出。

### 对象释放与资源结束

deinit 可以做最后的同步清理，但业务上的结束不必等到对象销毁。一个页面仍被导航缓存时，可以已经停止订阅；任务已经收到取消时，底层操作却可能尚未关闭；对象消失也不代表外部系统已确认注销。这些事件需要通过明确的停止、取消、关闭或等待协议连接起来。

Swift 的 borrowing、consuming 和非复制类型进一步表达借用、所有权转移与不允许任意复制的值。它们可以帮助封装唯一资源，也会影响参数传递和后续可用性；普通可复制结构体与这种显式所有权约束不能混为一谈。

UnsafePointer 等接口允许直接访问存储，但有效期、初始化状态、访问边界和释放匹配要由调用者保证。把临时指针带出其有效作用域，即使外层 Swift 类型检查通过也可能产生错误。跨语言资源封装需要把这些责任与原生对象、任务的寿命一起设计，本篇先建立其位置。

## 调度、任务与隔离

### 从线程、队列到 executor

同步调用要求当前调用完成后再继续，异步调用允许通过回调或挂起恢复衔接后续过程。阻塞会占用线程等待，挂起保存任务的执行状态并让出运行机会；并发允许多项工作交错推进，并行则要求实际同时执行。一个 async 函数内部仍可执行很长的同步计算，这段计算不会因函数有 async 标记就自动移到后台。

线程承载指令执行，Dispatch 队列组织提交的工作。串行队列限制同一时刻执行的工作数量，并按队列规则处理提交；普通串行队列通常没有一条永久专属线程。并发队列允许多个工作重叠，实际是否并行取决于线程资源与调度。主队列与主线程之间有平台规定的关系，不能推广到所有队列。

Dispatch 的 sync 等待这次工作完成，async 提交后允许调用者继续；它们与队列是串行还是并发属于不同维度。若一项串行工作同步等待只能由自己结束后才可执行的工作，就会形成等待环。即使没有死锁，在主线程等待长操作也会阻止事件处理，在协作执行器上长期阻塞也会损害其他任务推进。

Swift Concurrency 的 task 表达整项异步工作，executor 负责安排其中可运行的执行片段。任务可以挂起并在以后恢复，恢复后的线程未必与挂起前相同；actor 隔离则约束哪些片段可以访问相应状态。由此，任务、队列、线程和隔离域之间并不是一一对应关系。

### RunLoop 怎样处理事件

RunLoop 属于线程的事件处理设施。循环检查需要处理的输入源与定时条件，在适当时候等待，再执行相应回调；Observer 可以观察循环阶段。应用框架驱动主线程循环，所以 UI 事件可以不断进入；普通工作线程若需要这类事件处理，则要安排运行循环的时机和退出条件。

mode 决定一次循环监控哪些源和定时器。同一个 Timer 即使已到期，若当前运行模式没有包含它，也不会仅因时间已过就立刻回调。common modes 是一组被标记模式及其关联机制，向 common 注册源并不意味着它在所有可能模式下都执行。

Timer 表达可处理的到期条件，回调还要等待线程和模式提供机会；线程忙于其他计算时，实际执行会延后。因此定时器适合周期性触发，不构成实时期限保证。页面计时展示若依赖真实经过时间，应在回调时根据时间依据计算，而不是假设每次回调间隔精确相等。

Dart isolate 的事件与微任务、JavaScript 的微任务规则、RunLoop 的模式与源，属于各自环境的执行模型。它们可以帮助提出“谁调度后续工作”的共同问题，但 Swift 的任务恢复与 Dispatch 提交不能直接套用某一种脚本事件队列顺序。

### async、结构化任务与结果汇合

调用 async 函数通常沿当前任务继续执行，await 标记可能挂起的位置，不会每次都生成一个新任务，也不保证一定发生线程切换。两个调用先后书写时，前一个结果可能是后一个输入；要让独立工作具备并发推进的机会，需要通过 async let 或 task group 明确创建子任务。

async let 适合数量在源码中确定的子任务，task group 适合按集合或条件增加工作。结构化作用域负责等待子任务终结，父任务取消也会传播给子任务。这个关系让调用方能知道何时整组工作已经结束，但仍要求子任务配合取消，否则退出作用域也可能继续等待。

task group 按完成情况提供结果，不承诺与加入顺序一致。若最终列表需要原顺序，应同时保存输入身份并重新整理；先把结果排序后打印，展示的就只是排序结果，不能反推执行顺序。

抛错组中，子任务失败与父任务观察到错误是两个时刻。错误在消费对应结果时传播；组闭包抛错退出会取消并等待其他子任务。正常退出时，未消费的子任务错误不会自动变成调用者的错误，所以需要根据目标选择收集所有结果、遇到首个失败退出，还是允许部分成功。

### 非结构化任务与合作取消

Task 初始化器创建非结构化任务，可以继承创建位置的 actor 上下文、task-local 值和相应优先级。detached 不继承相同的 actor 隔离和 task-local 上下文，可独立设置优先级。两者都不会因为外层函数返回就自动形成结构化的等待关系，也不能把普通 Task 当成随意切到后台的开关。

非结构化任务适合由页面模型、服务或其他对象明确拥有的异步过程。拥有者保存句柄，用于接收结果、请求取消和确认终结；如果任务可以比创建者活得更久，就需要说明谁继续管理它。是否保存句柄不会决定任务一定执行与否，但会影响后续能否控制和观察。

取消是合作请求。任务可以读取标记、调用 checkCancellation，或使用 Task.sleep 等响应取消的 API，再按约定结束。未检查标记的循环、没有取消协议的回调来源，都可能继续工作。任务取消还可能与成功回调同时发生，底层取消、状态更新和结果恢复因而需要同步与幂等规则。

“取消已请求”“取消已观察”“任务已退出”“资源已关闭”是不同阶段。await 任务结果可以确认任务已经结束，能否同时确认资源关闭取决于任务实现。defer 在真实退出时清理，取消处理器则用于及时连接底层取消；二者不能简单互相替代。sleep 和 yield 可以让出执行机会，却不能证明另一任务已经到达指定位置，需要确定先后关系时应使用明确的协调协议。

### actor 的隔离与重入

actor 把可变状态放入隔离域，通过串行执行片段避免任意并发访问。外部异步调用通过 actor 的执行安排访问状态；方法中的同步片段运行期间，同一 actor 不会同时执行另一段隔离代码。但方法一旦挂起，actor 就可以接收并处理其他工作。

因此，一个 actor 方法从进入到返回不一定构成完整事务。库存检查通过后，方法可能挂起等待外部确认；另一个请求此时也通过检查并完成扣减，原请求恢复时再沿用旧判断就可能超卖。这里始终没有同时读写内存的数据竞争，错误来自跨挂起点的条件已经变化。

解决方式取决于状态协议。可以在恢复后重新检查，将检查与扣减放在同一同步片段；也可以先预留库存，失败时回滚；复杂流程还可以保存版本或请求身份，拒绝过期结果。actor 提供隔离的基础，具体业务不变量仍由这些操作关系维护。

MainActor 是供多项声明共享的全局 actor，常用于 Apple UI 相关状态与接口。不同实例 actor 则各有隔离域。nonisolated 接口不要求进入该 actor 执行，但也不能据此直接访问其隔离可变状态。判断 UI 可否更新时，应先依据声明与框架的隔离要求，再考虑当前调用如何进入相应域。

### Sendable、状态转移与执行设置

Sendable 描述值跨隔离域传递时满足的并发安全契约。由安全成员构成的值、受 actor 隔离的引用，以及使用可靠同步保护状态的类型，都可能提供相应保证。结构体里含着未同步的可变对象时，不能仅凭外层是值类型就认为安全。Sendable 闭包还会约束捕获的内容，使其符合跨域使用要求。

Sendable 并不会给任意对象自动加锁，也不证明业务顺序正确。unchecked 声明把验证责任交给实现者，适合已经有可说明的同步或外部保证的场合，不能用来消除尚未理解的诊断。sending 则可以表达将一份值转移到另一个隔离上下文，通过限制后续使用来避免同时访问，与要求值能够自由共享的契约有所区别。

Swift 6 language mode 加强并发检查，模块还可以配置默认 MainActor 隔离。Swift 6.2 的 NonisolatedNonsendingByDefault 特性会让非隔离 async 函数默认沿调用方隔离执行；未开启时，需要按原有执行规则判断。concurrent 属性显式选择在并发执行器执行 async 函数。因此，相同的函数外观在不同模块设置下可能有不同隔离含义，分析时需要同时查看声明与构建选项。

锁适合保护短同步临界区，actor 适合通过隔离接口管理异步共享状态。需要线程配对解锁的锁不能依赖挂起前后仍是同一线程，长时间阻塞也不适合作为协作任务的常规等待方式。采用哪一种机制，要看访问是否同步、状态由谁拥有，以及临界区能否跨异步过程保持成立。

### 回调桥接与持续数据流

continuation 保存异步调用的恢复点，可以把一次回调接回 async 控制流。调用方挂起，回调到来后恢复结果或错误；恢复发生在任务调度关系中，不意味着后续代码立即就在回调线程执行。单次 continuation 必须恰好恢复一次，漏恢复会使等待无法结束，重复恢复则违反契约。

checked continuation 能帮助诊断错误使用，但无法自动决定成功、失败、超时和取消谁赢得结果。若底层 API 允许竞争回调，需要用状态机和同步保证只有一个恢复者，同时处理迟到回调与资源注销。仅仅把回调包进 continuation，不会自动补出完整取消协议。

AsyncSequence 为消费者提供逐项异步读取接口。AsyncStream 常用于把推送事件接入这种消费方式，由生产端 yield 值，再通过 finish 表示不再生产。生产完成后，缓冲中已有值仍可以继续消费；消费者取消、迭代自然结束和底层订阅关闭则需要分别安排。

生产快于消费时，要决定保留哪些值。AsyncStream 的有界缓冲可以保留较新或较旧元素，yield 会报告丢弃情况，但不会因此等待消费者逐项接收。允许丢弃的实时状态与要求无丢失的事件日志需要不同协议；背压要求生产者能感知消费能力，不能仅靠设置一个缓冲容量获得。

onTermination 可以连接底层订阅的清理，但回调只在实现确实执行注销时才证明资源结束。提前停止消费也应显式安排订阅和流的寿命，不能只看到循环退出就推断外部生产已经停止。
