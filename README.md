# 原生客户端学习

基于已有的 Flutter 复杂客户端开发经验，系统补充 iOS 与 Android 原生工程能力。技术主线为 Swift + SwiftUI、Kotlin + Jetpack Compose，学习围绕客户端的原理、机制、架构、实现与验证展开。

文档贯穿学习过程，应用工程、独立语言实验、图示和诊断产物为正文提供实现与验证依据。业务场景按当前问题选择，优先取材于已有 Flutter 实践。

## 已有经验与学习起点

已有实践涉及实时数据与共享订阅、请求竞争与迟到结果、复杂导航和表单状态保留、K 线视口与高频更新、跨语言调用与资源所有权，以及缓存隔离、启动和构建发布。这些经历提供问题认识、工程约束和设计判断，原生实现与运行证据随本项目的学习逐步形成。

已有原生实践随实际需求穿插开展。本次系统学习 Swift、Kotlin 的语言、标准库与运行机制，并在客户端场景中建立和验证理解。

每个主题仍需完整交代背景、问题、错误行为与预期结果，再建立当前平台的机制解释。问题和业务要求可以相近，语言、内存、任务、UI 与宿主生命周期的语义需要分别说明和核验。已有经验帮助确定起点和重点，讲解深度由理解问题所需的内容决定。

必要背景直接描述在本项目中，各篇核心正文能够独立恢复主要理解，工程文档提供具体实现和验证入口。

## 推进方式

九个能力域保证知识覆盖，四个阶段控制学习深度。同一套正文随实验、实现和验证持续完善。

1. **建立运行模型**：理解工程、构建、启动、页面、任务、状态更新与资源结束的完整链路。
2. **掌握核心机制**：从完整问题出发，深入语言运行时、并发、生命周期、UI、状态和数据，核对已有判断在原生环境中的成立条件。
3. **形成架构与平台能力**：组合代表性场景，处理模块协作、依赖、共享资源、系统能力与互操作。
4. **深化诊断与交付**：固定运行条件，通过性能分析、故障验证、测试和构建产物核对工程判断与实际效果。

每个主题沿“问题背景 → 本平台机制 → 架构判断 → 工程验证”推进。先说明触发条件、错误行为和预期结果，再通过实现、实验及异常场景核对判断，将结论补回正文。网络与服务端行为统一由 [Node mock 服务](shared/services/README.md)模拟；系统生命周期与平台行为在对应运行环境中验证。

## 文档分工

根目录 `docs/` 完整解释问题背景、当前平台的机制细节、架构判断、取舍与失败边界，保留必要的 API、短代码和验证方法。语言工程的 `docs/` 维护语法、API 表达与独立实验，应用工程的 `docs/` 维护当前实现设计、配置、源码入口、运行步骤和实际验证结果。具体职责与跨篇分工见 [核心知识入口](docs/README.md)。
